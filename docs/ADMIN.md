# Кабинет организатора

## Первый администратор

Регистрация с сайта отсутствует. Администратора создаёт оператор на сервере после миграции `npm run db:migrate`. Стандартного логина/пароля нет; seed не создаёт админов.

`npm run admin:create -- organizer` получает пароль из файла, заданного `ADMIN_PASSWORD_FILE`, либо из stdin. Секрет не передаётся аргументом, не выводится в консоль и не попадает в Git. Файл секрета монтируется при настройке сервера вне репозитория. Логин: 3–64 латинских символа/цифры/`_`/`-`; пароль: 12–256 символов. Повторное создание существующего логина завершается ошибкой и не меняет пароль.

В БД хранится соль и scrypt-хеш (N=32768, r=8, p=3, профиль OWASP 32 MiB). В cookie — случайный 256-битный токен, в БД — только его SHA-256. Сессия действует 12 часов. На production cookie HttpOnly/Secure/SameSite=Strict; production требует HTTPS. Выход удаляет серверную сессию; старый cookie после выхода не даёт доступа.

Ограничения входа общие для всех процессов: 10 попыток для логина за 15 минут и 60 попыток за минуту глобально, счётчики в PostgreSQL. Нет привязки участников к IP/NAT. Вход не раскрывает существование логина.

## Проведение опроса

1. Открыть `/admin` и войти.
2. Создать мероприятие. Постоянный адрес можно указать самостоятельно или оставить пустым для автоматического выбора; после создания адрес не меняется.
3. Добавить нужные группы, отредактировать их названия. Код группы также постоянный. Слово `screen` зарезервировано для экрана проектора.
4. Добавить вопросы, указать группы, число и длину ответов. У вопроса может быть несколько групп.
5. Скачать QR SVG/PNG или скопировать ссылку нужной группы, открыть экран проектора.
6. Нажать «Запустить вопрос». Вопрос автоматически станет активным для назначенных групп; участникам не нужно сканировать новый QR.
7. Использовать «Пауза», «Продолжить» и «Завершить». Переключение вопроса и повторный запуск сохраняют ответы.
8. Архивировать мероприятие после встречи. Ответы сохраняются; восстановление возвращает доступ к мероприятию, но открывать вопрос нужно явно.

Копия мероприятия содержит только группы, настройки и вопросы-черновики: ответы и активное состояние не переносятся. Вопрос с ответами удалить нельзя. Группу с вопросами удалить нельзя; нельзя переназначить уже ответившую группу или снизить лимит ниже реально принятого числа ответов.

## Границы текущего этапа

Ручная модерация, алиасы, CSV и режим репетиции — шаг 3. GigaChat — шаг 4. Список ответов не отдаётся анонимному клиенту; показано только одобренное частотное облако. Внешнего сервиса аутентификации нет.

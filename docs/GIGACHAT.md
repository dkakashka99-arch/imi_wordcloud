# GigaChat — настройка и работа

ИИ анализирует выбранные организатором уникальные слова с частотами, предлагает объединения, слова для модерации и 3–5 наблюдений. Частоты облака рассчитываются PostgreSQL без модели. Все предложения требуют отдельного решения человека. При сбое ИИ телефон, проектор, ручные правила и CSV продолжают работать.

## Серверная конфигурация

По умолчанию `GIGACHAT_ENABLED=false`. Для включения на отдельном российском VPS нужны:

- `GIGACHAT_AUTH_KEY` или смонтированный `GIGACHAT_AUTH_KEY_FILE`. Значение не содержит префикса Basic. Не использовать NEXT_PUBLIC-переменные.
- `GIGACHAT_SCOPE=GIGACHAT_API_PERS` для подтверждённого личного аккаунта; B2B/CORP — только для соответствующего типа аккаунта.
- `GIGACHAT_CA_BUNDLE`: PEM-файл корневого и выпускающего сертификатов из официального источника. Клиент добавляет их к стандартным корневым только для HTTPS-запросов GigaChat. Глобальное отключение TLS блокирует включение клиента.
- `GIGACHAT_MODEL`: проверенный ID доступной модели. Пустое значение означает обнаружение через `/v1/models` и выбор только `GigaChat-2` или `GigaChat` (Lite). Платные пакеты автоматически не подключаются.
- `GIGACHAT_TIMEOUT_MS=20000`, допустимо1000–60000; `GIGACHAT_MAX_INPUT_WORDS=150`, допустимо1–300.

Ключ в Actions Secret используется только отдельной проверкой на вымышленных словах. Для приложения на VPS секрет настраивается отдельно. Он не извлекается из GitHub обратно в чат/файл проекта. Workflow не печатает токен, ключ или ответ модели. Присутствие секрета и его пригодность подтверждаются статусом OAuth/моделей/чата, а не чтением значения агентом.

Сертификаты скачиваются по HTTPS с обычной проверкой цепочки с официального gu-st.ru, проверяются OpenSSL. Каждый PEM нормализуется `openssl x509` до объединения, чтобы не склеить границы без завершающего перевода строки. TLS-preflight выполняется без credentials с `-verify_return_error`. Отпечаток публичного сертификата допустим в диагностике; ключи — нет. Не использовать отключение TLS или curl -k.

## Работа организатора

Открыть вопрос → «Модерация и экспорт» → GigaChat. Выбрать действие, проверить список слов, убрать персональные сведения и подтвердить отправку. Передаются слова, частоты и номера групп; названия групп, cookie/ID участников и исходные строки не отправляются. Email/телефоны/IP/ссылки и очевидные полные имена фильтруются автоматически. Автоматический фильтр неполон: организатор обязан исключить остальные имена/сведения в предпросмотре.

Результаты хранятся с revision, моделью, временем анализа, пакетом слов и usage. «Применить алиас» меняет правила группировки; «Скрыть эти ответы» меняет approved; исходники сохраняются. Отклонённое предложение не применяется. Алиасы можно отменять в ручных правилах, ответы — возвращать в панели модерации. Резюме появляется на проекторе только по кнопке одобрения; его можно убрать. При новых ответах или изменении правил прежнее резюме автоматически скрывается; применение устаревших предложений отклоняется.

Запрос ждёт результата модели, но не держит транзакцию/блокировку вопроса. Только глобальная session advisory lock PostgreSQL сериализует генерацию между инстансами: занятый клиент сразу получает429. Лимит6 новых задач/минуту и пауза20секунд на вопрос, кеш по revision/типу/модели/пакету. Запущенная задача после потери владельца помечается interrupted при следующем запуске. Модельные запросы не повторяются после неоднозначного5xx/timeout;401 вызывает один повтор с новым токеном. OAuth обновляется заранее, single-flight, с одним коротким retry для429/5xx.
